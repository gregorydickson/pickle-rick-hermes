# Attract — Submit DOT Pipeline to Attractor Server

Submit a `.dot` pipeline file to a running [attractor](https://github.com/strongdm/attractor)
server for execution. Validates locally, submits via HTTP, monitors status with
exponential backoff, and handles human gate questions.

## When to Use

- User says "attract", "submit pipeline", "run the DOT file"
- User has a `.dot` file from pickle-rick-dot
- User wants to execute an attractor pipeline

## Prerequisites

- Attractor server running (default: http://localhost:7777)
- DOT file generated by pickle-rick-dot (or manually)
- Optional: `ATTRACTOR_ROOT` env var pointing to attractor repo

## Step 1: Acquire Pipeline

Find the DOT file:
1. Explicit path from user
2. Most recently modified `.dot` file in current directory
3. Most recent pickle-rick session's `pipeline.dot`

If not found, ask user.

Parse flags:
- `--detach` — submit and exit without polling

## Step 2: Validate Locally

Find attractor root (check `$ATTRACTOR_ROOT`, then `../attractor/`, then auto-detect):

```bash
terminal(command="test -d $ATTRACTOR_ROOT/packages/attractor && echo OK || echo 'NOT FOUND'")
```

Validate the DOT file:
```bash
terminal(command="cd $ATTRACTOR_ROOT && bun packages/attractor/src/cli.ts validate DOT_FILE")
```

Errors → show diagnostics, stop. Warnings → show, continue.

## Step 3: Check Server

```bash
terminal(command="curl -sf ${ATTRACTOR_URL:-http://localhost:7777}/health | jq .")
```

If unreachable:
1. Check Docker: `docker compose -f $ATTRACTOR_ROOT/docker-compose.yml ps`
2. Offer to start: `docker compose up -d`
3. Poll health for 15s

## Step 4: Submit Pipeline

```bash
terminal(command="curl -s -X POST ${ATTRACTOR_URL}/pipelines -H 'Content-Type: application/json' -d '{"dot": "DOT_CONTENT"}'")
```

Extract `PIPELINE_ID` from response.

Save checkpoint:
```json
{
  "pipelineId": "PIPELINE_ID",
  "dotFile": "DOT_FILE",
  "url": "ATTRACTOR_URL",
  "timestamp": "ISO_DATE"
}
```

If `--detach`: print pipeline ID and resume command, stop.

## Step 5: Monitor Execution

Poll with exponential backoff (5s start, 30s cap, reset on state change):

```bash
terminal(command="curl -sf ${ATTRACTOR_URL}/pipelines/${PIPELINE_ID}")
```

**Terminal states**: completed, failed, cancelled, timeout, paused

**Human gates**: Check for pending questions:
```bash
terminal(command="curl -sf ${ATTRACTOR_URL}/pipelines/${PIPELINE_ID}/question")
```
If question exists: present to user via clarify, submit answer:
```bash
terminal(command="curl -sf -X POST ${ATTRACTOR_URL}/pipelines/${PIPELINE_ID}/questions/${QID}/answer -H 'Content-Type: application/json' -d '{"value": "ANSWER"}'")
```

## Step 6: Report Results

On terminal state:
1. Print status, pipeline ID, duration
2. Fetch final context: `curl -sf ${ATTRACTOR_URL}/pipelines/${PIPELINE_ID}/context`
3. If failed: suggest checking logs, viewing events, resuming from checkpoint
4. If completed: celebrate

## Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `ATTRACTOR_URL` | `http://localhost:7777` | Server URL |
| `ATTRACTOR_API_KEY` | _(unset)_ | API key for auth |
| `ATTRACTOR_ROOT` | _(auto-detect)_ | Path to attractor repo |
| `POLLING_TIMEOUT` | `3600` | Max polling time (seconds) |

## Security

- **NEVER** log, print, or echo API keys
- Store keys in `.env` (ensure `.gitignore` includes it)
- Mask keys in error responses before displaying
